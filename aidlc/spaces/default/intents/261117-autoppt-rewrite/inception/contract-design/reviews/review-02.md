### Answers to the specific questions

- **R-09, the app property (assumptions text).** The statement is accurate. Drive's `appProperties` are private to the app that wrote them, and the Drive documentation ties that to the OAuth client ID. The developer's wish to say it is "tied to the app, not the client id" would be false, so stating the real limit is right. It is acceptable here. One shared setup file means one client id for every operator, so `files.list` with `appProperties has {key='autoppt' and value='slides'}` finds all of them. The only loss is a replaced setup file with a different Google client, and then sign-in has to be redone as well. The assumption names the fallback (the shared `properties` field).
- **TooLarge (R-12).** Acceptable. FR5.11 asks for a plain reason for a request over 500 verses, and no earlier kind fits. The kind is additive, one more enum value, with no effect on existing consumers. It is disclosed in the Assumptions as going beyond the Q5 list, so the owner can reject it. No change is needed unless the owner objects.
- **Java blocks against the C2 tables and C5 types.** Consistent. All 10 ports in components.md are present. Every type used in a signature is defined in C5 or is a JDK type. Method names match the C11 tables.
- **Port types.** No port exposes a Google, ESV or library type.
- **Names.** No `Ppt` or `Deck` appears in a component, type or tag name. The only hits are in the sentence that forbids them and in the assumption that quotes the old `deck` value.
